# Spark + Workers Free staging

Keep Firebase Spark unchanged. Create a Cloudflare account on Workers Free, not Paid. The server uses SQLite Durable Objects, one private object per room; Firebase remains the identity and existing app database provider. No service-account private key is required or stored. Set the verified Firebase project ID, web API key and database URL in a local copy of wrangler.toml; use Wrangler secret put ARENA_ROOM_SECRET for a strong randomly generated secret (32+ chars). Copy the verified arena-vocabulary-v1.json from the successful full-source audit into this directory. Run npm install, npm run free:check, then npm run free:deploy only after owner approval. Do not enable a paid plan. Never paste secrets in chat or commit them.

This is a staging implementation, not a release. Test Workers Free CPU, duration, daily request/write quotas, auth account-lookup compatibility, room quota, actual alarm behavior, two/four-device sessions and 70-word generation before activating Android origin. 20 rooms per authenticated UID per day; lobby expiry 10 minutes, finished room retention 24 hours. Full answer keys are private. The verified bank currently has no YDS/word-type metadata; unavailable choices must be disabled or imported. Live Firebase rules remain untouched. Existing Android users keep their installed package and data. If quota is exhausted, service should fail closed and never auto-upgrade.

## Connected GitHub build
Use root directory `tools/arena_v150_server`, build command `npm install && npm run free:prepare && npm run free:check`, and deploy command `npm run free:deploy`. The prepare step extracts only the existing dictionary from public v1.0.148 APK, pins its SHA-256 to the audited source dictionary, and refuses mismatches. It downloads the APK on the build machine, not on user devices. Keep automatic builds disabled until the dry-run CI passes and runtime settings are configured. Keep the three Firebase values in Settings > Variables and Secrets, plus a unique ARENA_ROOM_SECRET of at least 32 characters stored as Secret. keep_vars preserves dashboard variables during future deployments. No service account key is needed.
